# 蓝牙同步设备 v0.3.7 固件烧录手册

## 适用范围与准备

本手册用于本地Windows、ESP32-C3主从板，开发版本0.3.7-dev。日常使用、密码和网页入口另见使用手册。先确定角色与当前COM口；COM8、COM6只是本次实物端口，换口后应重新核对，不能只按旧端口猜测。

主端为ESP32-C3＋ML307 V5.1，从端为ESP32-C3。烧录期间保持可靠USB供电，关闭占用相同串口的监视器；不带电插拔SIM。屏幕接线保持不变。不要同时运行两套程序操作同一串口。

## 镜像和分区选择

| 文件 | 用途 |
|---|---|
| master-ML307-v0.3.7-dev-app.bin | 当前主端APP更新，偏移0x10000 |
| slave-C3-v0.3.7-dev-app.bin | 当前从端APP更新，偏移0x10000 |
| master-ML307-v0.3.7-dev-flash0.bin | 通用全镜像，只供与其分区布局完全匹配的新板；不能直接用于当前COM8原厂分区板 |
| slave-C3-v0.3.7-dev-flash0.bin | 通用全镜像，新机用途，更新已有实物不使用 |
| manifest.json、verification.json | 文件长度、SHA256、源码与内嵌网页一致性；不等于整机验收 |

文件位于firmware/dist/v0.3.7-dev。当前主端实测4MB Flash、双OTA，app0为0x10000、大小0x1A0000；从端app0大小0x300000。只能给正确角色烧录对应APP。普通更新保留bootloader、分区表、OTA选择、NVS、MQTT/WiFi/CA和BLE缓存，不整片擦除。

## 更新前备份

1. 先使用当前后台密码认证，通过USB或本地“设备”页导出配置。备份含密码，保存在firmware/private或自己的可信目录，不能提交Git或公开发布。
2. 配置备份不包含整个Flash、运行计数和BLE缓存。原始整片Flash备份和每次烧录的保留区备份另存private。
3. 核对manifest中的SHA256与文件长度。当前APP不得超过实测分区容量。
4. USB认证文件只需包含password字段。不要把密码直接写进命令行或截图。通用新机密码88888888；已有设备按自己的实际维护密码。

导出示例：.venv/Scripts/python.exe -X utf8 firmware/tools/usb_maintenance.py --port COM6 --auth-file firmware/private/com6-auth.local.json --backup-file firmware/private/backups/slave-before-update.json。备份目标需是新文件，工具拒绝覆盖已有备份。

## 推荐APP更新命令

在项目根目录依次执行，等待前一步成功再继续：

主端：.venv/Scripts/python.exe -X utf8 firmware/tools/flash_app.py --port COM8 --role master --version 0.3.7-dev

从端：.venv/Scripts/python.exe -X utf8 firmware/tools/flash_app.py --port COM6 --role slave --version 0.3.7-dev

工具先验证镜像清单、芯片容量与实测分区，并备份0至0x10000；主端还备份已存在的扩展NVS。只更新0x10000的APP。写后校验APP，再比对保留区，全部通过才复位启动。USB读传输不完整时拒绝备份；写后读失败可用已验证前置备份与芯片摘要比较，不直接重写APP或跳过保护。

每次日志、备份与verification.json存入firmware/private/device-flash/带时间和角色的目录。工具核验失败时先看日志；未写入与已写入但校验失败的恢复方式不同，不盲目重复或擦除。

## 启动配置与本机密码策略

烧录成功还需分别检查启动、配置版本、storageOk、屏幕探测、上网、MQTT和后台。通过usb_maintenance.py的只读diagnostic与独立backup回读验证配置，没有串口写成功就等于实机全部通过的规则。

本项目实际板子烧录后须核对firmware/private/device-maintenance-policy.local.json中的apPass和adminPass。已匹配时不要额外写入或重启；不匹配时才使用--apply-policy，并在重启后回读。私有策略只留本机，不进入固件或发布包。不要覆盖上网WiFi、MQTT、目标绑定及缓存。

## 维护网页与保存重启检查

按使用手册打开热点，连接后访问http://192.168.4.1。必须看到角色对应的分页和真实状态；后台密码框不回显。保存前记录版本与必要参数，保存后热点会关闭，重新开启连接后核对版本增加、域名/用户名仍在、密码设置标记仍有效。

写入或回执超时先回读；不能连续点击保存或盲目重试USB写入。配置版本冲突应先刷新，CSRF失效重新读页面。当前通用维护密码只用于首次初始化，普通升级保留NVS，不静默改成88888888。

## 主端存储迁移与回退

v0.3.7在当前原厂已有smsdata NVS分区内创建独立项目命名空间，迁移有效配置和项目记录；不修改分区表或格式化，原默认NVS记录保留。该板迁移前已单独备份并核对原分区用途；其他板不能盲用同名分区。

升级后继续使用正常导出/恢复流程。回退到只识别旧默认NVS的固件，可能读取迁移前旧配置，而非新分区的最新版本；回退前必须另存当前配置并评估格式兼容性，不能宣称APP回退就还原了模组内部AT/证书/RTC或所有运行状态。

配置损坏时保留记录，不清除整个NVS冒充恢复。恢复出厂是独立破坏性操作，应由用户明确选择；不作为普通升级或故障排查的默认动作。

## 在新电脑准备工具

安装Python3.12与Git，取得私有源码仓库后，在项目根目录执行：py -3.12 -m venv .venv；再执行.venv/Scripts/python.exe -m pip install -r firmware/requirements-dev.txt。PlatformIO第一次编译会下载固件依赖，需联网且留足磁盘空间。源码清单使用固定版本的ESP32平台、ArduinoJson、U8g2；BLE库版本见工程依赖与构建日志。

串口驱动取决于板子的USB接口，本次两板使用ESP32-C3原生USB串行/JTAG。Windows设备管理器中确认实际COM口，不能直接沿用别人机器的COM6/COM8。首次烧录和升级都先核对硬件容量、角色、分区和保留数据。

若确为全新空白且与通用镜像分区完全匹配的板子，可用esptool将对应flash0镜像写到0；这会覆盖引导和分区布局，不能用于当前原厂主端更新。只有已单独确认允许初始化的新板才执行整镜像流程，现有两板统一使用上方APP更新工具。

## 从源码编译与验证

本地使用Python虚拟环境、PlatformIO和已安装ESP32工具链。执行firmware/tools/build_release.py，再执行firmware/tools/verify_release.py。Windows构建目录使用本机ASCII路径，避免中文工具路径兼容问题。版本、源码哈希和内嵌HTML原文/gzip均由清单检查。

原生回归数量以当版evidence日志为准，，本地DOM106项、远程DOM64项使用模拟外设或传输。另记录真实APP写入与读回、参数加载、实际热点网页、WiFi/4G/NTP/TLS/MQTT、采集上传/从端缓存/广播状态及设备执行回执。独立射频抓包、功耗、深睡跨日和长期稳定性未完成，hardware_accepted仍为false。

## 常见问题

串口不存在：检查USB数据线、供电和端口列表，主端深睡也可能使USB消失；短按RESET，避免同时按BOOT进入下载模式。串口被占用：只关闭占用该板串口的程序，不停掉其他用户程序。屏幕不亮：核对SH1106四针接线，默认会息屏，短按BOOT；I2C ACK不能代替实屏确认。

维护热点连不上：确认热点已打开、已有密码没被当成初始密码；Windows可用已保存profile手动连接，等待DHCP后访问。无需因此开启系统位置权限。MQTT连不上：分别核对上网、校时、CA、认证、订阅授权和设备执行回执，不把服务器PUBACK当成所有业务已成功。


## USB完整性与CA保护

新版USB使用BTLOCAL2帧，JSON正文前有字节长度和FNV校验码；请求与回包都检查。校验码只防传输截断、丢字节和损坏，不代替后台密码认证。旧BTLOCAL帧仅允许认证的只读诊断和备份，配置/恢复需新版工具，不能降级为不校验的写入。更新固件后配套更新usb_maintenance.py。

一次现场USB恢复曾使CA正文中间丢32个字符，JSON仍合法，旧流程仅检查版本号未发现。现在除帧完整性外，还在提交前用设备的X.509解析器检查CA；恢复工具重启后导出配置，逐项核对提交值。出现transport_integrity_failed、回包校验失败或超时，先回读再决定操作，不能自动重复写入。

真实CA、WiFi与MQTT密码从自己的离机备份恢复，不从公开手册或示例拷贝替代。诊断只显示错误类型、TLS错误码、证书验证标志、socket错误和MQTT返回码，不打印密码或证书私钥。


## 本版范围与升级后维护入口

v0.3.7当前推荐r1修订（demo-v0.3.7-r1），仅完成软件验证与编译，未烧录或实机验收。r1检查软件重启维护意图位于RTC no-init区域；不要选旧初包。现有COM6为其他设备，本轮不操作串口。重新接入项目板时必须先确认芯片身份、角色和分区，不凭旧COM号烧录。

普通APP升级保持原NVS与全部密码。老配置没有maintenanceBootSeconds时默认120秒。主端短按RESET或重新上电后保留维护窗口；保存重启也保留。定时唤醒、自动故障重启不额外等待。显示锁和原业务计划照常生效。

既有v0.3.6固件与实机摘要保留为历史。本轮不进行实际长测或续航，不把这些待验收项写成已通过。公开版只有通用固件及脱敏资料；公开仓库只提供通用镜像，真实账号、密码、私有绑定和Flash备份均未包含。
