屏幕与 BOOT 按键

开屏默认大数字时钟，上方显示连接和电源图标；短按逐页查看总览、滚动码、蓝牙、网络、上传/接收、设备及维护信息。主端电池为模型估算，从端为 USB 外接供电。滚动码显示来自最新已采集/收到字节，不预测或解密。

关闭显示锁时可直接翻页，长按 BOOT 约 3 秒打开维护热点。屏幕自动熄灭、再唤醒或深睡后重启时，开启显示锁的设备仅显示默认时钟。

开启显示锁后，在 10 秒内完成 BOOT“短、短、按住约 1 秒；短、短、按住约 1 秒”。未解锁时无进度、错误或长按反馈，也不能打开维护热点；解锁后才可翻页和长按开热点。RESET 会重启，不参与密码输入。

显示锁只限制本地查看和热点入口，不停止扫描、联网、MQTT、接收或广播。它不等于 Flash/MQTT 数据加密。C3 深睡不能直接由 BOOT 唤醒；可等定时唤醒或短按 RESET，避免同时按住 BOOT 进入下载模式。

本地维护后台

解锁后长按 BOOT 约 3 秒，连接设备热点，浏览器打开 http://192.168.4.1，用户 admin。热点密码与网页登录密码是不同配置，上网 WiFi 密码又是另一项。手机可能提示无互联网，维护时保持连接该热点。

主端后台为概览、网络、蓝牙、计划、设备；从端为概览、网络、模拟、设备。状态采用卡片和分组，大段 JSON 仅在折叠诊断内。页面使用真实 API、密码认证、CSRF、版本冲突检查与参数校验。

保存会先确认持久化，再安排重启。重启关闭维护热点；重新长按开启并连接。密码框留空表示保留，不回显已有密码；域名、用户名和其他非密码字段应正常读回。版本冲突时刷新后再编辑，不连续重复提交。NVS 空间不足会明确失败，不清空旧配置冒充成功。

WiFi 测试使用 2.4GHz 路由器或手机热点。从端正常联网依赖 WiFi；主端正常工作用 SIM/4G，维护热点不是上网网络，主端 WiFi 未连接不等于 4G 故障。后台可检查实际注网、MQTT、扫描、接收、广播、最近时间和诊断。

配对与原始广播

主从使用一致的主题前缀、主设备编号、目标 MAC、generation。每台设备自己的编号必须唯一，账号按权限使用。从端只接受所选主端的有效快照，拒绝错误来源、过旧序号、错误代次和非法帧。

原广播保留 MAC、地址类型、PDU、ADV 与 Scan Response 的分界及原字节。ADV/RSP 各不超过 31 字节；不能把扫描工具拼接的整串 raw 全填进 ADV。PDU 不能从仅有的拼接 raw 推断，应依据原采集元数据。

跟随模式使用主端最新有效快照并保存缓存。重连收到相同 retain 数据不会把原采集时间改成当前时间。掉网时继续广播最后有效缓存，过期会提示，不伪造新数据。

固定模式填写 MAC、固定 ADV、RSP、PDU，保存后广播这些固定内容，不接受 MQTT raw 更新；WiFi、每日校时和本设备远程控制仍工作。

同类型默认滚动码为合并 raw 从 0 计数字节 25 起取 4 字节，镜像偏移 42。后台可配置。两处不一致时显示不一致，不拼接、解密或预测下一值。

每日校时与主端省电

所有计划按北京时间 UTC+8。主端每次蜂窝 TLS 建连前校时，常在线时相隔上次成功满 24 小时执行有界 MNTP；先设置模组 UTC 时区，解析得到 UTC epoch，再由屏幕/网页显示北京时间。从端用 WiFi SNTP，每日一次，固定模式同样执行。

每日调度与失败分支已有软件检查，真实首次校时已通过；尚未完整运行 24 小时，不能宣称每日长期验收。RTC 有效但暂时断网时继续使用已有时间，不伪造新的校时成功记录。

主端省电开启时最多五个每日时段；开始早于结束、不可跨午夜或重叠，结束可到 24:00。默认 08:00–08:15、20:25–20:35，可修改或清空。时段内完整采集并取得本次 QoS1 PUBACK 成功一次后结束，保存结果、正常关机、进入深睡；旧缓存不算本次采集。

每段有尝试次数和总预算，过期不接受迟到 PUBACK。失败补报，已完成的同日开始点去重。零时段仍保留每日校时/收取待办机会。主端关闭省电则持续在线，按扫描/上传间隔工作；当前实物为联调临时常在线。从端固定常在线，不提供深睡开关。

自动恢复与耗电控制

主从均无独立联网批次冷却，不恢复旧六小时等待。保留可调逐次退避、单次连接超时、主端工作预算和可选有限自动重启。新机默认退避 10 秒起，逐次增加到最多 60 秒；已有自定义设置升级保留。USB 认证错误限频与联网恢复不同。

模组内部自动重连关闭，由 ESP 单一状态机管理。ESP 单独重启时先有界清理旧 MQTT 会话。关机最多两次 AT 尝试，识别实际 POWER OFF；未确认时记录电源未知，不伪装已经断电。

主端每日校时失败不会因为该次 AT 错误主动拆除健康 MQTT 会话；真正断网仍触发正常恢复。屏幕、网页和 UART 不并发抢占模组。

远程工作台与云端权限

打开 https://bedtimeenforcer.github.io/esp32-c3-ml307-ble-public/ 。先导入本机 private 中的无密码连接资料，再填网页专用账号；不要使用云平台管理员、API Key 或设备账号。请按本仓库docs/部署远程控制台.md创建自己的连接资料；示例只含占位符。

网页经 WSS 8084 /mqtt 直连中国区私有 EMQX，不需要额外服务器。静态程序公开，设备数据由账号和 ACL 保护。费用上限保持 0，未升级付费，保留用户指定的临时平台 API。

每台设备使用一个授权设备子树订阅，加上主端 raw；两台共三条。最多八台设备时共九条。云端规则必须对应实际设备编号，新从端增加独立设备编号及其授权，不放开整个主题空间。

页面显示主从状态、滚动码、最后更新、时段、历史和执行回执。无设备数据时显示尚未上报；状态过旧显示未知；收到遗嘱显示断开；预计深睡不是设备仍有电的保证。

保存远程设置携带配置版本、独立指令 ID、过期时间。服务器 PUBACK 只表示收下指令，必须收到设备 done 才代表执行成功。深睡设备要等下次联网处理。重复投递不重复执行，过期不执行，冲突需刷新；浏览器退出不停止设备。

密码只用于本次 MQTT 会话，不放入 URL、程序源码或 localStorage；退出清空页面数据。浏览器可能按用户自己的密码管理器设置保存密码。无密码连接资料会保存在本机浏览器便于再次登录。

电量与后续验收

主端电量由 5V 侧容量及活动/睡眠/蜂窝电流模型粗估，不是读取稳定 5V 得到电芯真实百分比。满充后手动标记已充满，异常掉电可能失去校准。估算 0% 不永久停机。续航目标要经过整机测流和放电实测。

后续验收包括独立射频抓包、实屏各页/锁键、断网与掉电恢复、多从端、跨日时段与深睡、错误 CA/身份负向检查、实际每日校时、整机功耗和长期稳定性。当前 hardware_accepted=false。

v0.3.7：配置备份与恢复

登录本地维护后台，切到“设备”：

1. 点“下载配置备份”，确认文件含WiFi、MQTT和维护密码，再保存到可信位置。备份不会上传云平台。

2. 恢复时选择同角色JSON备份，确认替换设置并重启。主端与从端备份不能混用。

3. 恢复使用当前设备的配置版本做冲突检查；备份中的历史版本号不会回退当前版本。原校验、NVS双槽提交和重启回读仍生效。

4. 若维护或上网密码改变，按备份中的参数重新连接和登录；不能因为密码框不回显就认定保存失败。

5. 取消文件选择、取消确认、角色不符或格式无效均不写设备。

认证USB工具增加--backup-file与--restore-file。例如先用--port COM6 --auth-file firmware/private/com6-auth.local.json --backup-file firmware/private/backups/slave-config.json导出；恢复时用--restore-file指定该文件。导出拒绝覆盖同名备份，终端不打印配置值。USB与HTTP恢复共用同一保存校验，写入超时应先回读，不能直接重复提交。

备份只包含配置，不包含BLE缓存、运行计数或整个Flash；设备存储完全丢失后还需核对数据代次和序号连续性，不能靠配置文件自动恢复所有运行状态。

v0.3.7：故障与诊断

SIM通信错误采用最多5次查询、每次短间隔重试，仍受工作预算限制。SIM PIN/PUK需要用户在手机等设备处理，程序不会自动猜码。ERROR代表有响应，不等于已关机；正常关机得到确认后，下轮可在同一次运行中再次启动。没有关机确认时保留物理电源状态未知及短退避，不反复按电源键，也不恢复6小时冷却。

配置校验或JSON解析失败时，原记录保留，后台提示恢复备份或明确重置；不会把这种情况静默当新机覆盖。若底层命名空间或整片NVS丢失，普通Preferences接口仍可能只能看到“缺失”，离机备份和原始镜像因此需要另外保留。框架/Flash硬件的损坏不因应用层双槽而自动消失。

远程诊断显示固件、SIM与配置状态，并标出诊断更新时间；诊断不能替代新的在线心跳。常在线状态心跳为60秒，150秒无有效上报显示未知，避免对100MB/月卡制造不必要流量；实际账单仍需统计。

当前实物状态与日常检查

主端已使用4G联网，从端已选择跟随主端并启用蓝牙广播；关闭网页或不解锁屏幕都不影响后台业务。联调期间主端持续在线，从端保持USB供电和2.4GHz上网热点开启。请使用自己设置的维护、WiFi和MQTT账号密码。

历史v0.3.6已分别验证主从联网、真实远程扫描上传、从端快照一致和广播状态、远程配置回执及本地完整表单保存重启。本版v0.3.7尚未实机验证。CA损坏会明确拒绝保存，旧配置保留；USB工具检查帧完整性并在重启后逐项核对提交值。手工换CA时应使用完整PEM证书，不能只复制BEGIN/END两行。

本地页面保留分页卡片，主端为概览/网络/蓝牙/计划/设备，从端为概览/网络/模拟/设备。电脑或手机重连热点后，获取到的本地地址可能改变，等待DHCP完成再打开192.168.4.1，不把连接中或旧地址当成网页故障。

当前仍未完成独立射频抓包、完整24小时与跨日深睡、整机功耗和长期稳定性，开发版本不等于整机已经验收。固件镜像、备份、更新和故障回退只在单独的烧录手册中操作。

RESET维护窗口：非工作时段如何维护

主端开启省电后，先松开BOOT，再短按RESET，或重新上电。主端完成启动后默认保持清醒120秒；本地“设备 → 复位后的维护窗口”可调整30～300秒。窗口从启动完成起计算，不要求4G、MQTT或校时先成功。

1. 开屏仍是默认时钟。启用显示锁时按原规则解锁，窗口不会自动解锁或自动开放热点。

2. 解锁后长按BOOT约3秒打开维护热点；连接后访问192.168.4.1。

3. 热点开启期间禁止深睡；有人连接时保持维护，闲置关闭时间沿用已有设置。

4. 不想继续维护，可在“设备”页点击“结束维护，恢复计划”。收到确认后约0.5秒关闭热点，随后由原计划决定是否深睡，不会强行中断正在执行的采集任务。

5. 保存、恢复配置或明确重启后，会再次保留维护窗口，方便重新连接。正常定时唤醒和自动故障重启不额外等待120秒。

有效BOOT按键释放会给当前人工操作保留时间；卡住不松的按键不会无限续期。窗口只阻止过早深睡，不停止时段内扫描、上传和正常调度。窗口未用尽也不绕过显示锁。BOOT(GPIO9)不能直接从此C3的深睡中唤醒，需先RESET；勿同时按RESET和BOOT进入下载模式。

例如只配置08:30～09:00，晚上维护时采用RESET→解锁→长按BOOT→连接热点即可。没有进行人工操作时，维护窗口超时后恢复原深睡计划。上述为本版实现与软件验证流程，实物尚未验收。
