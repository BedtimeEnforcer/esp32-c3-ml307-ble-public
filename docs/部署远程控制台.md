# 部署远程控制台

remote-web是静态网页，通过WSS访问自己的MQTT Broker，不需额外HTTP后端。网页公开不等于MQTT数据公开。

## GitHub Pages

1. Settings → Pages选择Deploy from a branch，main分支和根目录，保存。
2. .nojekyll禁用Jekyll，根index.html跳转remote-web。访问https://bedtimeenforcer.github.io/esp32-c3-ml307-ble-public/，或https://bedtimeenforcer.github.io/esp32-c3-ml307-ble-public/remote-web/。
3. 复制到其他账号后使用该账号/仓库对应地址；也可将remote-web上传其他静态托管并保持vendor相对路径。仓库中的所有文件均会公开，不提交私人配置。

## MQTT和权限

按服务商实际域名、TLS/WSS端口、路径和CA配置。EMQX常见WSS 8084、/mqtt，但以实例为准。创建主端、从端、网页各自受限账号，不用平台API登录网页。

主题为btclone/<prefix>/<masterId>/raw和btclone/<prefix>/<masterId>/devices/<deviceId>/...。网页读取所选设备子树及raw，发布仅限其cmd子树。设备发布自己的state/config/history/ack/presence/diagnostics并清理已处理cmd，主端另发布raw；从端订阅raw和自身cmd。不要授予全主题权限。

导入firmware/examples/remote-connection.example.json并替换占位符，填写自己的网页账号。密码只在当前会话中使用，不放URL、代码或localStorage；退出清空设备数据。离线设备需等联网执行，Broker PUBACK不代表设备done。

firmware/examples/mqtt-acl.example.csv提供占位符权限清单。先替换三个用户名、配对前缀、主编号和两台本机编号，使其与设备和网页一致，再按平台当前CSV模板导入（pub发布、sub订阅、allow允许）。不要照抄示例用户名作为真实共享账号，不启用超级用户；保留拒绝其他主题的兜底规则。设备cmd发布权限用于删除已执行的retained命令，漏掉会反复收到旧指令。

设备TLS需服务商完整CA证书，不仅是BEGIN/END两行；主端校时成功后才建立TLS，从端需可用2.4GHz WiFi。校验失败不通过关闭证书验证来规避。网页使用自己的WSS端口/路径，MQTT设备TLS端口不能填入浏览器WSS端口。

验收顺序：先分别确认两设备网络、时间和MQTT认证，再确认raw订阅与各设备子树SUBACK；网页选择主端执行一次扫描，等设备done后核对从端最新快照及广播状态。越权主题必须拒绝。完成这些实测后才记录硬件结果；仅网页连Broker成功不代表BLE射频验收。

本仓库不提供真实账号、私有实例地址或配对数据。云服务额度、区域和费用以服务商为准。v0.3.7维护窗口仅经过软件验证；页面不会伪造设备在线。
